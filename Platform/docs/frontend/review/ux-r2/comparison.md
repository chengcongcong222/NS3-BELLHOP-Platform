## 截图证据与判断

### 1. 首页

- 证据：`legacy/01-home.png`、`r1/01-home.png`、`r2/01-home.png`。
- 旧版的深色框架和高密度导航很像完整软件，但任务路径不够自解释。R1 补齐了案例与工作流，但横向顶导航加大卡片仍像网站门户。R2 用固定主导航、紧凑当前模块条和服务状态把首页接入同一工程工作台。

### 2. 环境建设

- 证据：`legacy/02–04-*.png`、`r1/02–04-*.png`、`r2/02-environment-list.png`、`03-environment-detail.png`、`04-environment-profile.png`。
- R1 的 SSP、Bathymetry 和 coverage 语义准确，但输入与预览分散在报告式 panel 中。R2 把左侧输入、中央声学剖面和右侧构建状态组成连续空间；海面、海底、深度/距离尺度与正式 coverage 同时可见。无正式声线数据时不画伪声线。

### 3. 场景工作台

- 证据：`legacy/05-scenario-workspace.png`、`06-node-selected.png`；对应 R1 和 R2 同名文件。
- 旧版的成熟资产是“工具—画布—属性—状态”同屏；R1 虽能拖动和编辑，画布只是一张小卡片。R2 恢复三栏工作台，同时保留 R1 的 N 节点与精确坐标。`06-node-selected.png` 实证 N10/N20 双选、1966 m 三维距离、平面链路强调、节点属性和深度条同步。

### 4. 实验配置

- 证据：三代 `07-experiment-configuration.png`。
- R1 已比旧版更好地按场景、网络、通信和执行分组，但单列大表单增加滚动。R2 用紧凑桌面分区、单位和即时校验保留语义，主要参数可在 1440 px 宽度内比较。

### 5. Run Monitor

- 证据：三代 `08-run-monitor-start.png`、`09-run-monitor-active-link.png`、`10-run-monitor-statistics.png`。
- R1 只显示最后链路和平铺 KPI；R2 把状态/仿真时间/进度收紧到顶栏，左侧节点图例、中央网络画布、右侧链路检查和底部分层指标/趋势/时间线同步。`09` 的 N30→N20 Overheard reception 以节点光晕、方向连线、阶段标签和详情共同表达，不只是换 edge 颜色。
- Completed Run 新增“事件回放”：播放/暂停、拖动、0.5×/1×/2×/4×、重置。wall clock 只决定已记录事件的展示速度，不改 Run lifecycle、simulation clock 或 runtime state。

### 6. Result

- 证据：三代 `11-result-overview.png`、`12-result-detail.png`。
- R1 已保证 Backend AcceptanceReport 是 verdict 唯一来源，但仍是 panel 集合。R2 以左侧分析导航和“总览 → 网络/信道 → 融合 → 条件性 Acceptance → 证据”层级取代同级卡片，用户可以从结论逐级追到正式证据。

## 协同视图验收

- Scenario Canvas ↔ Node Properties：单击/拖动更新属性和坐标；Shift 双选立即显示距离与链路。
- Scenario Canvas ↔ Depth Profile：节点深度使用同一草稿数据，选中节点共用高亮。
- Run Topology ↔ Timeline：时间线事件选择决定当前 Transmission/Signal/NoArrival/Reception 阶段。
- Run Topology ↔ Current Link/Node Inspector：链路、发送节点、接收节点与详情共享当前事件。
- Trend ↔ Event Time：趋势横轴是仿真时间，点选会移动回放游标。小样本用点/事件标记，不拟造平滑曲线。

## 3D 决策：B，本轮明确暂缓

这个结论不是只因为依赖成本。旧版 Scene3DView 是 Studio 的可切换辅助视图，实机主流程仍依赖平面与剖面；它提供一般性空间定位，但未证明正式传播路径。R2 `06-node-selected.png` 在单个桌面视野中同时呈现 X/Y、节点深度、选中链路和三维距离，对当前的节点布设任务比切换到独立 3D 视图更直接。

当前正式前端资源没有可供 Run 投影的 3D bathymetry/path 证据。现在迁移旧 3D 要么只重复节点空间位置，要么会诱导用户把装饰场景当成正式声场。因此本轮选 B：2D 平面 + 深度 Profile 对当前任务已达到更低认知切换成本。待正式 3D 海底或传播路径投影可用时，再以同样的证据门禁重评。

## 桌面尺寸审查

- 1920 × 1080：Run 画布、分层指标、趋势和时间线同屏；场景工作台保留完整三栏。
- 1440 × 900：主验收尺寸，场景工具/画布/属性与 Run 三区均不横向溢出；底部深入分析保持纵向滚动。
- 1280 × 720：核心工作区仍保持左/中/右关系，属性栏可编辑；次要分析在下方滚动，没有为手机布局牺牲桌面画布。

## 仍未达到旧版的地方

- 没有恢复独立 3D 相机交互；这是上述有证据的暂缓决策，不是已实现项。
- Environment Profile 只显示正式资产已提供的 coverage/SSP/Bathymetry；旧版更强的声线视觉在没有 path 数据时不会仿造。
- 移动端只保持可读折叠，未按 mobile-first 优化；产品目标仍是桌面科研工作站。

## 总体结论

R2 不是把 R1 的卡片换色，而是恢复了旧版最有价值的连续 Studio 组合，并保留新版更好的 Case workflow、正式事件精度、Result 层级、中文任务语言、错误状态和可测试性。可视化证据支持 R2 已从“网页仪表盘”收紧为“水声网络仿真工作台”，但本记录不宣布 UX 冻结。
