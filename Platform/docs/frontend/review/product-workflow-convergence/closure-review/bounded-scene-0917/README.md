## 1. 环境边界不能由声场距离伪造

现有 WOA 是一个位置的垂直声速剖面，保存的地形是一条距离—深度测线。Bellhop 的 horizontal_range 则是**两节点之间的距离**，不是地图 X/Y 范围。不能由这些数据推造任意三维海底或完整地理围栏。

工作台“环境与实验参数 → 基本 → 场景范围与安全距离”新增明确选择：

- 场景 X 对应所保存地形测线的距离；Y 方向使用同一剖面。这是显式二维试验假设，不是实测三维海底。
- 用户设置 X/Y 范围、距水面和离海底安全距离。X 必须在原地形有效区间内；原样本不外推、不补齐。
- 整个配置保存在场景草稿和本次 Run 的冻结定义中。编辑当前草稿不会改变历史运行的边界。
- 运行前检查正式轨迹覆盖、纳秒时间范围、全部分段位置、收发深度、SSP 深度及节点对最大/最小传播距离。
- 选择二维试验域后，再检查 XY 范围、水面/海底安全距离；轨迹段跨过地形折点时也检查，避免两个端点合法、途中撞山脊的漏检。
- 不自动拉回节点、不延长轨迹、不改变速度、不修改 Runtime 运动。非法路径返回 400 `SceneDomainViolation`，不创建 Run。

旧场景未选择该假设时，不把它自动当作已测绘区域：仍做能够从正式数据验证的水深/SSP/传播距离检查；没有地形坐标关系就保留独立地形图。任意海域的三维地理边界、多个 SSP 空间变化不在本轮假装完成。

Bellhop provider 保持原范围型声场查询。本轮范围检查不是新的三维声传播算法。

## 2. 上下图与时间轴

- 选择试验域后，俯视图固定该范围，X/Y 等比例；为保持比例可能留出视野空白，虚线框表示实际选定范围。
- 节点和地形在同一深度图显示，俯视图与深度图共用 X 域、SVG 宽度和横向边距。视口变化只改变显示映射。
- 地形只画所选试验域内已有样本及内部线性插值；不延伸到无数据区域。
- 滑块、刻度、各事件泳道共用标签列与绘图区；不是分别设置不同左边距。
- Runtime 的长说明折叠、事件堆栈内部滚动、筛选集中到时间轴菜单。没有用隐藏溢出裁掉指标凑“一屏”。

真实浏览器最终量测见 [live-view-proof.json](./final/live-view-proof.json)：

- 1440×900，页面高度 900；
- 8 个时间轴绘图区均为 x=155、width=1254 px；
- 每个节点上下图 X 像素误差小于 0.001 px。

## 3. 重新运行与观看进度

“按原配置重新运行”调用正式重跑 API，创建新的 Run ID，保留旧 Run。新页面带 `presentation=live`，事件数从 0 开始，只逐步展示实际已收到的日志。

真实 ns-3 状态立即展示：后端可以瞬时 Completed，前端仍在逐步观看。这两件事不混同。暂停、单步、倍速只影响观看位置；“从头演示运行”本身只重播日志，不重新计算物理状态。

浏览器通过 MutationObserver 记录了 0 → 1 → 2 → 后续事件；重新运行前后冻结 Scenario、Experiment 和最终 projection 完全相同。未人为延迟 worker。

## 5. 结果与验收参考

展示“参考要求 | 本次记录”，不自动输出通过或满足要求。

- 节点发送速率取本次冻结 Experiment 的精确 ID/version，不是默认补 60，也不是吞吐量。
- 误码率按目标接收证据统计，不把旁听混入；区分模式 A 的模型估计和模式 B 的波形逐比特统计。二者都不是硬件实测。
- 当前软件的“5 点”按节点编号 + 观测序号去重。同一个节点不同时刻可以贡献多条观测；不应等同于 5 个独立节点/测站。
- 当前融合窗口耗时为最早有效观测采样到融合结果产生，包含传输等待；不是 CPU 计算耗时。
- 完整“分布式探测周期”尚未单独记录，不能拿一个较小的融合窗口数值冒充整条业务链的周期。页面明确保留这一缺口。

直观理解特征融合：多个节点先形成方位等特征，特征经过网络实际交付，融合中心再根据收到的有效观测估计目标；不是把原始波形直接叠加，也不是一个“完成”勾选框。
