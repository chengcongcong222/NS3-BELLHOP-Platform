## 2. 参数：常用选择与算法细节分层

完整字段分类、来源和单位见 [参数审计](./parameter-audit.md)。

- 通信性能实验：运行网络业务，不要求融合；探测与定位实验：生成方位报告，只有网络成功交付的数据进入融合。
- “算法最少有效观测数”是当前融合策略，不是用户安排触发时刻，也不是要求相同数量的节点。当前实现策略下限为 5，不能解释成最小二乘的通用数学要求。默认折叠。
- “报告收集与融合耗时参考”仅用于人工对照，不是定时器、终止条件或 CPU 运算耗时；与算法设置分开。
- “通信周期数”“每个时隙”“保护时间”以周期/秒展示。当前 TDMA 计划时长为周期数 × 非汇聚节点数 × 时隙时长；保护时间已在时隙内，不重复计入。
- 网络刷新是重新规划间隔，不是读取调度表的频率。随机种子用于可复现，不是帧号。
- 模式 A 使用抽象接收噪声；模式 B 使用波形噪声谱密度。速率、频率、带宽、声源级、时隙和保护时间都实际保存并进入运行，不是假只读 preset。

当前真实执行能力仍限 3～6 节点、TDMA、直达/最短路径。未开放未接入的算法。模式 C 未实现，未放置无效开关。

## 3. ScenarioNotFound 与运行上下文

根因：用户 authored Run 的场景保存在冻结运行定义中，但运行页仍向静态场景 catalog 查询，因此 Run 可以完成而画布报“资源不存在”。

新增只读 `/runs/{run_id}/definition-context`，从该 Run 的冻结定义取得场景、实验和执行参数，校验摘要与资源 ID/version；不读取当前可变草稿，不回退静态案例。预置 Run 通过对应适配取得实际参数。模式 B 预置时隙按实际执行的 6 秒投影，而不是旧 manifest 的 4 秒。

旧服务缺少新接口时，前端可合并完整 Result 与已到 SSE 的正式位置样本进行有限回放；第一条未来位置不会冒充更早时刻的位置。缺少配置的字段如实省略。

## 4. 模式感知的结果分析

运行概览、网络性能、水声链路、波形通信、探测与融合五部分保留，采用紧凑量化表、累计趋势、样本数和 min/mean/max。运行页“查看结果”展示同一个 Run 的完整分析浮层；窄浮层自动换列，没有复制另一套统计。

模式 A 的模型 BER 与模式 B 的实测 bit errors/BER、CRC 分开。模式未知不默认为 A。通信业务未启用融合时明确说明，而不视为失败。

“缺业务包分母”不是模式 A 天生缺物理统计：目前两个模式都缺少部分业务级记录。页面仅展示能够严格计算的指标；目标接收解码比例不冒充业务交付率，物理发送数不冒充业务发包数，发送到接收处理结束的间隔不冒充完整应用端到端时延。缺失项集中在折叠的数据覆盖说明，不用大批缺失提示占据主分析区域。

仍缺：业务生成总包数/交付字节/完整产生时刻、碰撞与重传、最大多径时延扩展、逐条方位观测值/无效原因。没有伪造这些量。

## 5. 轨迹生产与场景布设

页面为轨迹目录、XY 与深度时间双图、生成参数栏。静止、直线、航路点、CSV、已有 UUV CLI 均使用同一种正式资源。X/Y/深度及速度分量分别输入，深度向下为正，在保存边界转换为平台负 Z。

采样间隔仅决定资源记录密度，不是 ns-3 时钟、动画频率或 MAC 帧周期。预览和 Runtime 在正式采样之间按时间插值，不依赖表单当前采样间隔，不静默外推。

节点绑定后可以“调整轨迹起点”：将整个路径做空间平移，另存不可变轨迹并更新绑定。源轨迹不改；时刻、速度、姿态不改；Runtime 不执行隐藏的坐标变换。没有引入隐式时间伸缩、延长尾点或重新求解 UUV。

运行前检查每条绑定的精确资源、版本、track 及 TDMA 计划时间覆盖。超时先保存草稿但不创建 Run，明确需要补充哪条轨迹；运行期查询越界仍由正式轨迹查询拒绝。修改参数并成功保存后清除之前运行失败的过期提示。
