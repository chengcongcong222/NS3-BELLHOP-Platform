## 人类用户视角结论

本轮之前，底层资源链已经具备 Environment → Trajectory → Scenario → Experiment → Run → Result 的技术闭环，但前端仍把它表现成多个平级产品，缺少明确的实验装配中心。用户需要自行记住资源之间的引用关系，属于“技术闭环、任务未闭环”。

本轮把普通用户路径固定为：

1. 单独建设必须离线计算的声学环境；
2. 生成或导入轨迹资源；
3. 在场景节点属性中完成轨迹绑定；
4. 在实验工作台集中确认场景、业务、路由、MAC、Channel 1 / Channel 2 和执行参数；
5. 创建正式 Run，在同一页面观察事件、回放并打开结果抽屉。

服务器 Authoring Workspace 仍保存草稿，但不再作为一级产品模块；它是环境、场景和实验编辑页背后的持久化机制。

## 关键真实性边界

- WOA 请求显式给出经纬度、月份和目标深度；GEBCO 请求显式给出起点、方位、距离和采样数。使用固定参考缓存时，界面明确说明输入坐标不会改变缓存内容。
- 最大水深和最大距离来自实际 SSP / 地形点。若 SSP 未覆盖地形最深处，禁止进入 Bellhop 构建，不静默外推剖面。
- Channel 1 / Channel 2 是实验工作台中的正式配置，并随保存的实验草稿进入 Run；不是只改变界面的开关。
- 共享声学信道仍对全部可接收节点执行真实传播与接收处理。运行页默认展示协议目标链路以表达星形等逻辑拓扑，用户可切换到完整物理信道查看旁听；UI 过滤不删除正式事件。
- “从头演示运行”只逐步呈现已经存在的正式事件。真正重新执行通过实验版本创建新的 Run，前端不建立第二套仿真时钟。

## 早期数据缺口记录（当前状态见第三批记录）

- Run/Experiment 只读 DTO 尚未把 `physical_layer` 作为独立产品字段返回，运行页只能显示接收质量模式，不能可靠地写出 Channel 1 或 Channel 2。
- 结果投影尚缺业务包总数、交付字节、端到端产生时间、碰撞/重传和最大多径时延扩展，因此这些指标继续显示“未提供正式数据”，不从接收次数推算。
- 融合结果尚未保留逐条方位值、采样时间和无效观测原因；当前只展示正式保留的来源身份、有效数量、轮次、耗时和估计结果。
- 历史 Run 没有“以完全相同冻结定义再次运行”的专用 API；当前入口回到确切 Experiment 版本再创建新的 Run。
