## 已打通的执行链

工作台实验配置 → 后端验证 → 不可变 v2 运行定义及 SHA → Worker →
独立周期输入 → 只读规划 → 每周期新计划 → ns-3 → 真实事件与结果。

- CommunicationOnly 明确源、目的和每周期包数，可无汇聚节点、双向、多目的。
- BearingFusion 以实验层业务接收点接收报告，不从场景 Sink 推断目的地。
- Direct/ShortestPath 不再依赖唯一 Sink；旧 ToSink 策略只保留于兼容路径。
- AdaptiveTDMA 自动计算占用时间，按真实队列需求分配，不需要手工槽长。
- 相同周期与业务配置的生成时刻不因 MAC 机会位置变化；无机会仍入队。
- 实际 PHY 编码字节决定 airtime，模式 B 包括 CRC；环境上界覆盖插值、多径和旁听。
- 过旧来源版本、未知节点/下一跳、非法时序、跨周期占用均拒绝，不使用默认计划救场。
- 旧定义、旧 Acceptance、原通道1/通道2解调因果及正式轨迹继续兼容。

完整接口和兼容决策见 [ADR-0008](../adr/ADR-0008-adaptive-planning-execution.md)。

## 真实 Backend → Worker → ns-3 验证

使用真实发布环境和轨迹资源，每项均执行两个 60 秒周期。
“CRC通过/测量数”包含各物理接收方；旁听成功不能计为目的交付。

| 模式/配置 | 实际发送 | 目的交付 | CRC通过/物理测量 | 融合轮数 |
| --- | ---: | ---: | ---: | ---: |
| A / 2节点双向 / Adaptive | 4 | 4 | 不适用 | 0 |
| A / 3节点多目的 / Adaptive | 8 | 8 | 不适用 | 0 |
| A / 独立报告接收点 / Adaptive | 6 | 6 | 不适用 | 1 |
| B / 2节点双向 / Adaptive | 4 | 0 | 0/4 | 0 |
| B / 3节点多目的 / Adaptive | 8 | 0 | 2/16 | 0 |
| B / 独立报告接收点 / Adaptive | 6 | 2 | 6/18 | 0 |
| A / 2节点双向 / Configured | 4 | 4 | 不适用 | 0 |

模式 B 的结果保留参考浅海多径和简单接收机的实际表现，不将旁听 CRC 成功
改作目的交付，也不在不足5条有效报告时制造融合。旧正常/强噪声/缺失恢复数据/
融合因果门禁单独保留。自适应调度不能补救缺少多径均衡造成的波形失真。

另外验证：同一输入重复执行一致；混合格点传播上界；无轨迹不回退生成；
空帧继续积压；非网络更新周期执行新调度；中继积压进入下一周期需求；
零/多个 Sink 不改变显式目的路由；新模式不受旧 Acceptance 节点数模板限制。

## 仍明确留在后续的工作

后续范围已更新为 [服务端 C++ 算法与 XML 参数界面接入计划](server-algorithm-xml-plan.md)。规划型 MAC 包、XML 表单和第三方示例已完成首版，见 [接入指南](../../algorithms/README.md)。以下保留原阶段边界记录；其中 MATLAB 适配器已由用户取消，不再排期开发。

1. 当前为使用全局仿真信息的集中式需求调度基准；未实现分布式 TDMA 协商。
2. 通用结构当前是硬件能力相容的有向连通基准，不是基于实测反馈的链路预测器。
3. 未新增动态角色选举、融合窗口迁移、CDMA 或反应式 CSMA 执行接口。
4. 当前规划器无私有可变算法状态；AlgorithmMemory 的提交/回滚协议不能由 const
   接口自动保证。引入有状态算法之前须另做状态所有权与原子提交设计。
5. C++ 插件式只读接口已具备；MATLAB/Python 外部交换协议、运行隔离、超时和
   包版本校验仍后置。本轮没有通用规则引擎或任意脚本上传执行。
6. 当前所有普通通信包仍是既有4字节基准 payload；可变包长/负载模型不在本轮扩展。
7. 当前计划准入是保守的单信道串行占用模型；未来 FDMA/CDMA 等并行计划
   需要先补正交资源与冲突语义，不能关闭校验后硬塞进现有 TDMA 边界。
