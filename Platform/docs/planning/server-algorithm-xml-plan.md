# 服务端 C++ 算法与 XML 参数界面接入计划

采用服务端源码集成、编译注册算法，XML 只描述配置表单。先用已有自适应 TDMA 验证接入流程，再形成第三方示例包；不同时新增协议算法、动态加载框架和通用规则引擎。MATLAB 规划适配器不再开发，旧阶段记录中“后置 MATLAB”不再代表当前计划。

当前已实现规划型 MAC 的首条接入链：编译注册、Worker 目录、XML 参数表单、保存重开、运行冻结和精确重跑校验。首个正式包复用现有自适应 TDMA。第三方接入步骤见 [算法开发指南](../../algorithms/README.md)，增量约束见 [ADR 0009](../adr/ADR-0009-compiled-planning-mac-extensions.md)。没有网页上传任意代码、MATLAB 适配或协议热加载。

## 用户与开发者各自操作

- 普通用户在实验画布背景的算法设置中选择已安装算法。主界面只放节点、业务流、运行时长和物理模式；只展开当前算法的参数，提供单位、合理默认值和简短说明。
- 第三方开发者在服务端添加算法主体、XML 配置描述、单元测试及最小案例。管理员编译、验证、注册后才能供前端选择。第一版不接受网页上传任意代码，也不热替换正在运行的算法。
- 强拓扑依赖算法随典型案例发布，只开放经该算法验证的衍生范围。每个算法负责简短的场景校验，平台不维护庞大的跨算法规则推理器。

## 最小包边界

| 部分 | 职责 |
| --- | --- |
| 算法描述 | 稳定 ID、版本、所需接口版本、支持的运行模式与配置摘要 |
| C++ 主体 | 读取正式规划输入，返回计划；不直接调用 ns-3、改 Runtime 权威状态或在线求解 Bellhop |
| XML 表单 | 字段 ID、中文名称、类型、单位、默认值、范围、枚举、基础／高级分组；第一版不做字段间表达式 |
| 参数与场景校验 | 服务端严格检查未知字段、类型和算法前提；前端校验只改善交互，不充当权威 |
| 测试与案例 | 最小可运行实验、非法参数和不兼容场景、确定性、模式 A/B 门禁 |

XML 不包含脚本、动态求值或文件访问；构建时拒绝外部实体、DTD、未知字段和错误默认值。第一版提供类型化表单，不提供任意 XML 编辑器。加载失败的包直接使构建失败，不进入可运行目录。

## 运行时冻结与兼容

冻结内容至少包括算法 ID、算法版本、构建产物校验值、表单模式版本、规范化参数。重放查看原记录；重新运行必须使用原算法版本，缺少或不兼容则明确拒绝。升级默认值不能改写已保存实验或已冻结运行。

优先包装现有规划接口，不把内部头文件全部当作稳定 SDK。公开接口版本与包版本独立管理。参数表单只负责表达配置，不决定 Runtime 是否允许某类执行行为。

当前 PlanningV1 采用保守的单信道串行占用准入，适合规划型 TDMA 基准。反应式 CSMA 需要独立事件交互接口，CDMA/FDMA 并行执行需要正交资源与冲突语义；它们不能只加一个下拉项或 XML 页面就算完成接入。有状态算法还需先确定状态所有权、提交与失败边界。

## 接口与职责边界

选择算法不是一次场景转换。节点只保存收发能力和轨迹，业务流单独说明谁向谁发数据；MAC 决定发送机会，路由决定下一跳。融合处理位置属于应用算法，不属于节点硬件。后续角色选举需独立的周期角色策略接口，不能让 MAC 任意修改节点角色。

第一版公开 SDK 只接受只读快照、业务需求、周期长度和参数，返回发送机会数组。Runtime 继续掌握队列、实际发送、物理接收和提交；返回计划仍经过现有物理占用及周期边界校验。源代码包可在计算前检查节点数、能力及拓扑前提，并返回具体错误；平台不通过复杂规则表达式推断“某算法也许能运行”。

目前规划输入明确属于集中式全局信息模型。它不能代表节点只能利用本地观测的分布式协议。未来接入分布式或有状态算法时，先设计允许读取的信息、协议状态所有者、随机数流和提交／失败边界，再开放算法选项。

## 用户配置流程

1. 在实验工作台的“网络”中选择已安装算法。看到名称、简短适用说明和基础参数；高级参数默认折叠。
2. 选择新算法时初始化它自己的默认参数，不携带上一个算法的私有参数。切换算法不会改动环境、节点和通信流。
3. 参数使用人可读单位。例如界面填秒，保存仍为精确整数纳秒；不会把长整数强制转成 JavaScript 浮点数。
4. 保存草稿时后端检查完整的算法参数。其他尚未补齐的场景或业务配置仍可作为草稿保存；算法目录不可用或算法参数非法时，不假装保存成功。
5. 运行时再次核对包和参数，冻结完整定义。查看历史结果不依赖现存插件；按原配置重新运行必须具有相同执行程序，否则只能显式编辑并创建新实验。

旧实验不会自动转成注册包。兼容选项保留旧 Tdma／AdaptiveTdma 语义；新实验默认使用注册的自适应 TDMA。计算式周期仍是现有 PlanningV1 的业务产生与提交边界，不宣称所有未来 MAC 都采用该周期。

## 开发者安装与版本管理

开发者提供头文件主体、XML、测试和最小案例；管理员通过 `PLATFORM_MAC_PLUGIN_DIRS` 显式添加目录并编译 Worker。新增符合接口的包不需要修改前端页面、Python 算法枚举或 Worker 装配分支。第一版是头文件接入，复杂实现可拆成本包内多个头文件；独立静态库和动态库 ABI 后续再设计。

包摘要覆盖 XML 和本包头文件；它是配置身份，不是整个程序的替代摘要。冻结定义另记完整 Worker SHA256，网关在发送命令前读取实际子进程可执行文件的摘要进行核对，避免部署替换造成“目录版本和执行版本不一致”。当前这一检查使用 Linux／WSL 的 procfs。管理员部署时应使用新服务端口或停接新实验，不能在用户运行中原地热替换。

XML 是受限数据格式，C++ 仍是受信任的原生代码；第一版不是面向不可信租户的代码沙箱。接入评审必须检查非法 Runtime 访问、非确定性依赖、无限循环、越界、内存增长和异常处理。硬资源配额、隔离执行及依赖归档属于服务部署层的下一步，不用 XML 伪装成安全保证。

## 强耦合算法如何发布

强拓扑依赖的研究协议随典型案例发布：包括已发布环境引用、正式轨迹、场景、业务及默认实验配置，并在算法主体执行简短的适用条件检查。案例说明应列出可变项，例如节点间距、载荷或噪声，以及不可变前提，例如拓扑方向、移动节点数量。超出前提时明确拒绝，不自动“修正”用户场景。

当前不新建跨场景规则引擎，也不宣称已有案例限制编辑器；它是下一阶段的包交付规范和 UI 增量。通用算法优先，专用案例按真实集成需求增加。

## 扩展顺序与通过条件

| 阶段 | 当前状态 | 通过条件 |
| --- | --- | --- |
| 规划型 MAC 包与表单 | 已实现 | 旧新自适应 TDMA 逐发送机会一致；保存、版本锁定、A/B 与重跑贯通 |
| 第三方最小包 | 已提供，默认不安装 | 示例只用公开 SDK；通过额外编译目录接入，参数真实改变发送顺序 |
| 研究案例包、路由与角色策略 | 后续 | 明确适用条件、版本组合与实验对照；角色不进入硬件属性 |
| 反应式 CSMA 和有状态协议 | 后续单独评审 | 状态归 Runtime／协议实例；经 ns-3 事件合同实现退避、监听及超时 |
| CDMA／FDMA 等并发执行 | 后续单独评审 | 建立正交资源和干扰／冲突语义，不能绕开当前串行准入 |

MATLAB 规划适配器不在开发计划中。暂不新增算法市场、网页代码上传、自动下载依赖、动态 ABI 或通用规则语言。

每批均保留旧案例、轨迹、模式 A/B 和真实资源绑定回归；不存在版本自动替换、场景不兼容时自动换算法或算法失败时静默回退默认计划。
