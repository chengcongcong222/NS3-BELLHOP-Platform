# ADR-0008：自适应 TDMA 与只读规划接口

- 日期：2026-10-08
- 决策来源：用户要求推进“自适应 TDMA＋规划型算法接口”，补齐未关闭的通用执行边界。
- 状态：本阶段实施决策；测试与限制见阶段记录。不是新分布式协议或动态选举算法的验收声明。

## 新路径与兼容范围

新实验显式选择 `PlanningV1`，冻结为 `ns3-factory-authored-run-v2`。
旧 v1 定义、已有运行的 SHA、Acceptance preset 不被原地转换。
ADR-0001 的配置式 TDMA、首发送机会生成输入、网络更新周期复用旧计划，
仍适用于旧路径；新路径按下面规则运行。ADR-0006 的算法列表是当时的
实现范围，本阶段新增真实实现后的 AdaptiveTDMA 和通用 Direct。
ADR-0007 的只读展示约束继续生效，不以显示数据控制调度。

场景仍绑定不可变环境及轨迹。新路径允许没有 `fusion_center_node_id`；
该旧字段只用于 preset 兼容。硬件只决定能否收、发和双工能力。
CommunicationOnly 明确配置有向流（源、目的、每周期包数）；双向是两条流。
BearingFusion 在实验中配置业务报告接收点，不把它变为硬件类型或协议 Sink。
业务接收点本阶段固定，不等于已经实现动态融合服务迁移。

## 时间、业务与计划

业务周期时长是冻结输入，不由 MAC 机会数量倒推；轨迹覆盖时长是
周期数乘业务周期。所有新业务在每个周期开始的 INPUT_READY 阶段产生，
没有发送机会也入队，不能因换调度器而改变业务生成时刻或负载。

规划器只读 `WorldSnapshot`、`StructureSnapshot`、`PlanningInput`：
周期 ID、基础版本、边界时刻、每节点队列包数、当周期将入队的包数、
包占用时间上界和传播尾部上界。它不持有队列、内核、PHY、环境热查询或时钟。
这些输入明确标记为**全局仿真信息**，不是节点通过无线协议获取的知识。

返回完整 `ProtocolCyclePlan`，带来源版本和周期；提交前校验节点、能力、
路由、时间、重叠与闭周期完成条件。非法计划返回错误，不回退默认算法。
新路径每周期采用新计划；旧路径继续原有网络更新周期规则。
ns-3 始终是唯一时钟，周期边界不插入人为时间差。

## AdaptiveTDMA 的确切含义

这是确定性的集中式、需求驱动基准调度器，不冒称 ASMAC、ABMAC 或
已实现分布式自适应协商。它按队列与当前新业务需求进行轮转分配；
NodeId 排序，周期 ID 决定轮转起点，一个活跃节点获得一次机会后再轮到下一节点。
没有需求不占槽；帧内放不下的需求留在队列，以后周期继续规划。

用户不配置槽长。每次占用预算为：实际业务编码时长＋环境传播尾部上界＋安全余量。
模式 B 包含 CRC 字节；不按另一种业务的固定包长估算。
传播上界取整个已加载环境的最大首达时延，加最大多径超额时延。
两个最大值分别计算，以覆盖 provider 中“首达插值、路径取最近格点”的混合情况。
这是保证移动和物理旁听仍能闭周期的保守边界，不是瞬时信道优化。
模式 A/B 共用规划接口，保留物理层 0..N 接收和原有解调因果关系。

配置式 TDMA 仍可显式比较：新路径按所有可发节点排槽并检查固定周期能否容纳；
它不再暗含“除了中心外每个节点一个槽”。相同周期、流量、轨迹与 seed
构成算法比较的基础；不同队列结果和交付结果必须来自真实执行。

## 路由、角色与第三方边界

通用 Direct 对实际逻辑有向边建立目的路由，ShortestPath 为各目的确定最短路；
不从 Sink 角色决定所有业务目的地。当前通用装配使用能力相容的有向连通基准，
不声称它已判断水声链路可解调；物理到达和解码仍由真实信道/接收机决定。
角色表和角色策略仍是独立周期边界接口，可由未来算法替换；本阶段通用装配
使用 Member，不新增汇聚选举、CDMA 或任意拓扑约束规则引擎。

第三方 C++ 算法实现只读规划接口，再由装配显式选用。禁止在算法里直接
调用 ns-3、操作队列、生成业务或在线求解 Bellhop。
MATLAB/Python 的进程/文件交换适配器、版本化外部协议、超时和错误隔离
尚未实现；当前不提供“上传任意脚本即可运行”的产品承诺。

## 接口影响与迁移

- `ScenarioDefinition` 的旧中心字段改为 optional；NodeId 0 仍是真实节点，不是空值。
- `ExperimentDefinition` 追加可选 planning 配置，旧构造调用保持可用。
- planner 追加带 `PlanningInput` 的 Build；旧 Build 保留用于旧路径。
- 新 wire 命令不增加字段：仍通过冻结定义的路径和 SHA 加载，loader 区分 v1/v2。
- 新旧 worker/backend/frontend 须一同部署；旧 worker 不应被宣称支持 v2。
- 不修改冻结历史、既有资源文件或主工作区之外的 legacy。
