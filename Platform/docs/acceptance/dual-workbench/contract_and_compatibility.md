# 数据合同与兼容边界

本轮为 `feature/dual-workbench` 的整合收口。历史检查点报告保留，不将当时未完成的工作改写为当时已通过。

## 正式路径

| 对象 | 实现与约束 |
|---|---|
| authored v1–v3 | 原有几何场景路径保留；PlanningV1 的 A/B 方位业务新增可选、可校验的 `bearing_inputs` |
| authored v4 | 原双端点实录链路，不自动升级为代理网络 |
| authored v5 | `recorded_proxy` 包含每个实际可接收有向方向的完整 CIR、片段、增益、建模时延和每接收端噪声；无地理坐标查询 |
| A/B RunGroup | 一个共同快照、两个独立定义与 Run，后台单 Worker 顺序执行；任何冻结预检失败时不准入 |
| C RunGroup | 同一归档与队列所有者下的单 C 成员；不另建运行管理系统 |
| 重跑 | 从不可变归档恢复，重新校验资源、定义哈希与算法身份；不读取当前草稿来替换历史配置 |
| 重启 | 未完成成员标为 Interrupted；已保存结果可读、可导出；未归档事件明确不可回放 |

共同通信输入为版本化的确定性包清单；真实发送 PacketId、源和目的与清单比对。方位业务先用生产编码器离线生成周期起点报告，两侧清单必须完全相等；Worker 加载时重算验证，实际应用入队前逐条核对。该离线编码不是第二个仿真调度器。不同接收模型和编码 airtime 可产生不同计划、交付率和融合结果，不宣称两侧接收结果必然相同。

## C 时钟与接收

1. Tx 独立编码，各自通过所绑定的时变 CIR。
2. 发射时刻须落在接收通带采样网格和录音采样网格的共同整数纳秒量子上；不靠四舍五入改变物理到达。
3. Tx 相位采用包起点复位；接收机以目标到达为下变频参考。该假设写入冻结合同。
4. 在同一接收端的目标窗口截取并叠加已实际到达的信号，再加入一份连续接收噪声，最后真实同步、解调和 CRC 判决。
5. 其他发送端的真实比特不进入接收判决；判决完成后的误码统计可使用真值。CRC 假阳性保留，不用真值暗中“修正”成功与失败。
6. 新 `mixture` trace 仅含信号数、样本数及功率摘要；不传矩阵或原始比特。旧 trace 完全不增加该字段。

`PlanningInput` 新增只读 overlap admission 和 emission quantum，旧调用默认 false / 1 ns。仅 v5 混合接收装配开启重叠准入；同发送端 airtime 排斥、半双工、闭周期与 ns-3 时间权威不变。RegisteredMac 未开放到 v5，前后端均拒绝不支持的组合。

## 混合调制的明确适用范围

支持冻结的公共采样时钟/载频下 OSDM、BPSK、BFSK 逐发送节点配置。OSDM 为公共时钟基准；当前 BPSK/BFSK 预设为每符号 100 样本，速率由公共采样率确定。不同发送节点编码长度进入实际规划。接收机知道冻结的发送节点调制，不是盲识别、多用户联合检测或在线自适应调制。不能共用时钟/频带的配置拒绝，不隐式转换。

## 资源与持久化预算

- 资源载入预算：256 MiB，按唯一信道张量、每接收端噪声和载入瞬时副本估算；Python 与 Worker 双重检查。不是 BELLHOP/UWA 的物理极限，也不是整个进程 RSS 的硬上限。
- 信道张量在单 Run 内按完整身份复用；Worker 退出释放，不使用全局永久缓存。
- 波形各次计数转换预检不超过 10,000,000 样本；接收端另受配置的基带窗口预算限制，不能用无限长重叠窗口绕过。
- 单归档 32 MiB，超限拒绝；归档写入失败呈现 ArchiveFailed，可重试保存而不重新执行仿真。
- 浏览器只接收配置、结果、有限 trace 摘要，不接收 CIR 矩阵。

## 科研声明

D3 保持 **NO-GO**。本轮证明的是实录样本驱动的代理通信网络执行，不是一次真实多发一收海试的复现。全局同一 CIR、人为时移及跨链路噪声分配都是显式假设。Blue 的多个 receiver 是同次采集中的阵元，不能改称多发送源。Yellow/Purple 未经本轮完整数据和数值验收，不宣称全库支持。
