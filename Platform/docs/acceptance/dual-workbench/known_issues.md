# 已知限制与非阻断问题

1. 不部署主服务：本轮仅独立功能分支与临时验收入口；4182/8012 仍运行原版本。部署需单独授权。
2. 历史归档保留结果和冻结输入，不保留完整事件流；重启后的页面明确不提供历史事件回放，可执行原配置新 Run。
3. C 为代理网络，D3 真实多发一收证据仍 NO-GO。无任意位置查询、反向链路推断或 Bellhop 回退。
4. C 混合调制限明确公共时钟预设；接收机按冻结配置选择解调器，未实现盲识别、SIC 或多用户联合检测。
5. C 暂限 Direct 路由与配置式/自适应 TDMA。不能把 v5 的验证范围扩张为所有注册 MAC 算法均已支持。
6. 实测大样本验证限 Blue；第二阵元的官方短窗数值对照另行通过，但不是跨发射源共时性证明。
7. 桌面较矮窗口及 800 px 宽度使用纵向滚动；核心按钮可达，无页面级横向溢出。未开展整个平台非相关页面的重新设计。
8. Vite 仍有单包超过 500 kB 提示；Starlette 仍有旧 422 常量弃用提示。不影响本轮操作、数据或结果正确性。
9. 性能测量为本机 Debug 构建、指定 Blue 片段；不是大网络吞吐承诺。子进程峰 RSS 记录的统计范围已标明，不冒称持续瞬时采样。
10. C1 与代理子类型切换仍要求先保存并确认；两类一级工作台切换支持保存、保留缓冲区、取消。旧 C1 不自动转换为多节点代理实验。
11. 常规 backend 测试的可选项：本构建未安装 v2 示例算法包，因此未启用其专用 E2E；本轮不为验收激活算法版本。离线 Bellhop 可执行程序、netCDF4 不在此测试 venv，相关可选项跳过。需要真实录音/历史资源的项目另行显式执行，不计作“跳过即通过”。全部原因在 ctest 明细中保留。

负结果保留：早期旧 probe 路径导致 4309/4308 样本不一致；换为本工作树受测 probe 后通过。浏览器发现的结果页异常、缺绑定错误隐藏及 HTTP 500 已修复。一次几何拖动脚本在 800 px 视口外点击，修正定位并重跑通过；一次失败页面残留导致 CDP 导航停滞，重建测试标签后重跑。上述测试工具问题不作为物理结果的“修正”。
